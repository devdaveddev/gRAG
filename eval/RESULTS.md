# Retrieval evaluation

Reproduce: `python eval/fetch_corpus.py corpus.json && python eval/run_eval.py corpus.json eval/` (needs local Neo4j + Ollama with `qwen2.5:1.5b`, `qwen2.5:3b`, `nomic-embed-text`).

**Setup.** 8 overlapping Wikipedia articles (Apple, Microsoft, Google, Nvidia, OpenAI, Tesla, Amazon, Meta; ~7k chars each, 54-58 chunks).
40 questions generated by `qwen2.5:3b` from single anchor sentences (5 per article), so the answer location is known. A chunk is a hit if it contains >=80% of the anchor sentence's tokens. Top-5 retrieved.
*Conversational set* (39 questions): the company name is replaced by "it" and the chat history names the company, so only query rewriting can resolve it.
Models: `nomic-embed-text` embeddings, `qwen2.5:1.5b` query rewriter.

## Fixed-size chunking (1500 chars, 150 overlap)

| Retrieval | Single-turn R@1 | R@5 | MRR@5 | Conversational R@1 | R@5 | MRR@5 |
|---|---|---|---|---|---|---|
| Vector only | 72.5% | 100% | 0.823 | 41.0% | 71.8% | 0.541 |
| BM25 only | 67.5% | 87.5% | 0.742 | 61.5% | 76.9% | 0.682 |
| Hybrid (RRF), no rewriting | 75.0% | 92.5% | 0.815 | 59.0% | 76.9% | 0.663 |
| **Hybrid + query rewriting** | **80.0%** | **100%** | **0.868** | **74.4%** | **100%** | **0.848** |

## Semantic chunking (windowed-similarity boundaries)

| Retrieval | Single-turn R@1 | R@5 | MRR@5 | Conversational R@1 | R@5 | MRR@5 |
|---|---|---|---|---|---|---|
| Vector only | 62.5% | 95.0% | 0.773 | 43.6% | 79.5% | 0.590 |
| BM25 only | 60.0% | 85.0% | 0.695 | 51.3% | 74.4% | 0.606 |
| Hybrid (RRF), no rewriting | 65.0% | 85.0% | 0.740 | 64.1% | 76.9% | 0.687 |
| **Hybrid + query rewriting** | **72.5%** | **97.5%** | **0.821** | **69.2%** | **97.4%** | **0.814** |

## Findings (and caveats)
- Query rewriting + hybrid is the best setup in every column. On follow-up questions it lifts recall@5 from 71.8-79.5% (vector only) to 97.4-100%.
- Plain hybrid fusion without rewriting does **not** reliably beat vector-only on single-turn questions here (it is lower on recall@5 in both chunkings): BM25 over the raw question is noisy.
- Semantic chunking did **not** beat fixed-size chunking on this benchmark (MRR 0.821 vs 0.868). Wikipedia prose is already topically uniform, so it is not a good test for topic-shift chunking; it did give correct topic-aligned splits on a hand-built multi-topic PDF.
- Small sample: n=40 / 39, one question is 2.5 points, so differences of a few points are noise. Questions are LLM-generated and may share vocabulary with their source sentence. Small local models were used throughout.
